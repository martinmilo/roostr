# roostr 0.3.0

roostr now keeps `.roostr/` current instead of only showing where it fell behind, hands
coding agents the project map when they start, and speaks JSON to the tools that run them.

## New

- **`roostr check [--base <commit> | --staged | --session]`** says whether `.roostr/` is
  still true to the code. It runs the scan and compares what it finds with
  `entrypoints.tsv` (it never writes), checks every record as `validate` does, and lists the
  processes whose files changed after their record. With `--base` it judges only the work
  done after that commit and also reports new entrypoints that no process lists, or that
  lost the process that listed them. It exits 1 with what to fix, 0 when there is nothing,
  and 2 when it cannot run. `--staged` judges the commit being made, for a pre-commit hook:
  a change under `.roostr/` that is not staged would be left out of the commit, so it is
  reported. `--session` judges an agent's own work in its session, committed or not, for an
  agent's Stop hook: not the user's unfinished edits from before the session, nor commits
  brought in by `git pull` or a checkout, and not in plan mode.
- **`roostr session start`**, for an agent's SessionStart hook, notes the commit the session
  started at (in Git's own folder) and prints the **project map** for the agent's context:
  what to watch out for, how to start and test, and each process by group with its first
  files, in at most 8,000 bytes, as the JSON Claude Code, Gemini CLI and Codex take from a
  SessionStart hook. It is printed when a session starts, after `/clear` and after
  compaction, and is built from `.roostr/` alone (no Git, no scan). It reads the session id
  from the hook's input.
- **`validate` reports invisible characters** in `.roostr/` files and in record file
  names, such as text-direction controls and zero-width characters, since that text now
  reaches agents directly. Emoji and scripts that need joiners are not reported. Every text
  output writes such characters as `<U+202E>`, so a terminal or an agent sees them.
- **`validate` reports a file under `.roostr/` that is not a regular file** (a named pipe,
  a device), which roostr no longer opens.
- **`roostr init` says where the AGENTS.md line goes for Claude Code** (which reads
  AGENTS.md only where there is no CLAUDE.md) and Gemini CLI (GEMINI.md): a line
  `@AGENTS.md` in their file brings it in.
- **`roostr init` prints CHECKS**: Claude Code hooks for `.claude/settings.json`, a Git
  pre-commit hook and a CI line, each running `roostr check`. With the Claude Code hooks an
  agent cannot finish its turn while what it did in the session leaves `.roostr/` behind. In
  a project below the top of its repository, every hook and the CI line change into the
  project's folder first.
- **`checked` may carry a time**, `checked: 2026-11-06 14:32`, for a record confirmed more
  than once a day. `check` suggests the value to write.
- **`--json`** on `roostr`, `show`, `changes`, `validate` and `check`: one JSON object,
  `"format": 1`, same exit codes. The shapes and the rule for changing them are in
  FORMATS.md under "JSON output".
- **`roostr --version`** (and `-V`), and **`--help`** (and `-h`), which prints the usage and
  exits 0, also after a command.
- **Prebuilt binaries** for Linux (static, x86_64 and arm64) and macOS (Apple Silicon and
  Intel), with `SHA256SUMS`, attached to this release, each tested on its own kind of
  machine. They are named `roostr-<os>-<arch>`, so one install line fits all; see the README.

## Changed

- **Git 2.25 or later** is enough. 0.2.0 needed Git 2.31 and, with an older Git, the
  overview refused to run at all.
- **The overview still shows the map when Git cannot be read** (no `git` installed, or Git
  refusing a repository owned by another user). It says why, and leaves out LAST 7 DAYS.
- **A value over a length limit in `project.yml` no longer stops the overview or `show`.**
  `validate` and `check` report it.
- **`roostr show <id>`** suggests the ids you may have meant.
- **`validate` reports a group spelled like an area but not the same**, such as
  `Gift cards` for the area `GiftCards`, which put one area under two headings.
- **NEEDS ATTENTION follows merges more closely.** A record updated on a branch no longer
  counts as having seen changes that the main line made to its files in the meantime. After
  upgrading, such a record may appear under NEEDS ATTENTION; look at it, then set its
  `checked` date.
- **In a shallow clone** (the default in GitHub Actions' checkout), the overview says the
  history is shallow instead of showing NEEDS ATTENTION as empty, and `roostr changes`
  exits 2. Fetch the whole history (`fetch-depth: 0`, or `git fetch --unshallow`).
- **Ids, paths and names are printed whole.** 0.2.0 cut ids longer than 36 characters with
  `...` and broke long paths mid-word. A long name now stands on a line of its own.
- **Empty values count as absent.** A key with nothing after it, such as an uncommented
  `watch_out:` from the template, no longer makes the file unreadable.
- **`validate` reports more:** a key written twice in one file (the value written last is
  the one read, as before), an operation with no command or with a command of several
  lines, and a file such as `refund.yaml` or `orders/refund.yml` that looks like a record but
  is not read.
- **Names YAML would read as numbers**, such as an outcome `404:`, are taken as written.
- **A UTF-8 byte order mark** at the start of a file is ignored.
- **Hidden files** in `.roostr/processes/`, such as an editor's lock file, are not records.
- **A closed pipe keeps the exit code**: `roostr validate | head` exits 1 when there are
  findings.
- **A scan script that cannot be started** says why, for example a `#!` line with Windows
  line endings.
- **`roostr show` takes options as options**: `roostr show --verbose` is a usage error, not an id.
- The `validate` finding for a missing `entrypoints.tsv` now reads
  `.roostr/entrypoints.tsv: does not exist; ...` like every other finding.

## Upgrading from 0.2.0

1. Install 0.3.0 (see the README).
2. Run `roostr init` in each project. It leaves `.roostr/project.yml` alone and prints the
   new line for `AGENTS.md`: replace the old roostr line with it. The new line asks agents
   to run `roostr check --base HEAD` before each commit and before they finish.
3. Add the checks you want from the CHECKS section `init` prints.
4. Run `roostr check` once without `--base` to see what is already behind, and set the
   `checked` date of each record that still holds. It also lists what `validate` now
   reports and 0.2.0 did not, such as a key written twice.
