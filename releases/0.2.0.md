# roostr 0.2.0

roosty is now roostr. The command, the crate and the folder it reads in your project are
renamed, and nothing else changed: the commands, the file formats and the output are those
of 0.1.0 under the new name.

## Upgrading from roosty 0.1.0

roostr does not read `.roosty/`, and there is no `roosty` command any more.

1. Before you rename anything, run `roosty` once more and note what is under NEEDS
   ATTENTION. The commit that renames the folder counts as an update to every record, so
   those warnings will not come back by themselves.

2. Remove roosty and install roostr:

   ```sh
   cargo uninstall roosty
   git clone https://github.com/martinmilo/roostr.git
   cargo install --locked --path roostr/work
   ```

3. In each project, rename the folder in a commit of its own:

   ```sh
   git mv .roosty .roostr
   git commit -m "Rename .roosty to .roostr"
   ```

4. In the line `roosty init` added to your `AGENTS.md`, and anywhere else that names
   `roosty` or `.roosty/`, write `roostr` and `.roostr/` instead.

For a period that starts before the rename commit, the overview's LAST 7 DAYS and
`roostr changes` list every process as changed and do not compare entrypoints. A week after
the rename the overview is back to normal, and `roostr changes --since` any day after the
rename is right straight away.
