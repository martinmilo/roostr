## The problem this record serves

The Stop hook runs `roostr check --base HEAD`, so an agent that commits during its turn
slips past it: only the pre-commit hook and CI catch it (seen in a real run). The owner wants
to rely on several gates; this adds one, and replaces none. Separately, agents probe
`--help` and read its exit 2 as a failure, and roostr is to be released for macOS, where
nobody here can run the suite.

## Decided

### H1. The agent's session as a gate

**`roostr session start`**, for a SessionStart hook:

- Reads its standard input to the end, unless it is a terminal, and takes `session_id` from
  the JSON object there: the input every hook of Claude Code (and of Gemini CLI and Codex
  CLI) gets. `source` and every other key are ignored.
- Records the session's start in `<git dir>/roostr/sessions/<session_id>`, the Git folder
  being what `git rev-parse --git-dir` names: `.git` in a plain checkout,
  `.git/worktrees/<name>` in a linked worktree, which so has records of its own. The record
  holds the commit `HEAD` points at, or that there is no commit yet, and when the session
  started by roostr's clock (`ROOSTR_TODAY` is honoured). Its content is roostr's own and may
  change between versions.
- When a record for that id is there, it is kept: resume and compact keep the session's
  start. `/clear` and fork come with a new id, and so a new start.
- First it removes every record of a session that started more than 30 days ago (30 days
  exactly is kept). **Proposed:** removed before the session's own record is looked at, so
  a session resumed after more than 30 days starts again where `HEAD` is then. Claude Code
  removes transcripts after 30 days by default.
- Prints nothing on stdout, ever: a SessionStart hook's stdout goes into the agent's
  context. Exits 0 whenever it ran, also when it cannot record. Then it writes nothing, and
  says why on stderr in one line (**Proposed**; Claude Code does not show stderr of a hook
  that exits 0): an input with no `session_id` it can use (the message names
  `session_id`), not in a Git repository (`not in a Git repository`), or Git cannot be read
  (the reasons of "When Git cannot be read"). The hook then falls back, below.
- A `session_id` it would not use as a file name is no id: anything but ASCII letters,
  digits, `-`, `_` and `.`; empty; longer than 128 bytes; starting with `.`; not a string.
  So `../../hooks/pre-commit` writes nothing anywhere.
- It writes nothing else: never in the working tree, never in the index, nothing in the Git
  folder but its own records. **Proposed:** it needs no `.roostr/` and does not look for
  one: it records the repository's `HEAD` wherever it runs in a Git work tree, so that it
  works from any folder Claude Code is in.
- Usage errors (`roostr session` alone, another word than `start`, an option such as
  `--json`) exit 2 with the usage on stderr, as for every command.

**`roostr check --session`**, for the Stop hook:

- Reads the same input, and judges as `--base <the commit the session started at>`:
  everything done since the session started, committed or not.
- Falls back to judging as `--base HEAD`, exactly as today and silently, when there is no
  usable record: no input, input that is not JSON, no usable `session_id`, no record for it
  (the hooks were added mid-session), or a recorded commit that no longer exists. When
  stdin is a terminal it is not read: no id.
- A session that started before the repository's first commit judges everything in the
  repository as its work, as `--base HEAD` does in a repository with no commits yet.
- **Proposed:** when the session's start is the commit `HEAD` points at, `--session` is
  `--base HEAD`, also during a merge in progress (record 8's rule: the merged commits count
  as part of the base). A worker that compares the text `HEAD` would miss it; scenario 436
  pins it.
- With `--base` or `--staged`: exit 2, and the message says they cannot be used together.
  Outside a Git repository: exit 2, as `--base` is.
- JSON, additively: `base` is the full hash of the commit the session started at, `"HEAD"`
  when it fell back, `null` when the session started before the first commit; the new key
  `session` is the id read (when usable), otherwise `null`, and `null` without `--session`.
- Speed: with nothing changed since the start, as cheap as `--base HEAD` is today (2 Git
  calls). Once the session has committed code, every Stop runs the full check; accepted.
  Not tested.

**init.** The Claude Code line is still one line of JSON, now with both hooks:
SessionStart runs `roostr session start`, Stop runs
`roostr check --session >&2 || { [ $? -eq 1 ] && exit 2; }`. The CHECKS paragraph names
`--session`, and the Claude Code paragraph says the agent cannot finish while what it did in
the session, committed or not, leaves `.roostr/` behind, and that the start is noted in
Git's own folder. The AGENTS.md line keeps `--base HEAD`: that is what an agent runs by
hand.

**No `|| true` after `roostr session start`.** A SessionStart hook cannot block; a non-zero
exit is shown to the user as a hook error. A missing roostr (exit 127) then says so, once,
at the start of the session, and blocks nothing; `|| true` would hide it. Its "not found"
message goes to stderr, so stdout stays empty. The Stop line already turns any exit but 1
into a non-blocking error.

**Below the repository's top** (record 8's Raised 2 left the Stop hook out): Claude Code
runs hooks in its current folder, so at the top of a repository whose `.roostr/` is in
`services/shop` the Stop hook today finds no project, exits 2 and blocks nothing. init now
prints both Claude Code commands with `cd "$(git rev-parse --show-toplevel)/<folder>" && `
in front, which works from any folder of the repository:

```
cd "$(git rev-parse --show-toplevel)/services/shop" && roostr session start
cd "$(git rev-parse --show-toplevel)/services/shop" && { roostr check --session >&2 || { [ $? -eq 1 ] && exit 2; }; }
```

written into the JSON with each `"` as `\"`.

- **Raised 1: braces around the Stop command.** Written as the brief has it,
  `cd ... && roostr check --session >&2 || { [ $? -eq 1 ] && exit 2; }` parses as
  `(cd && check) || ...`: when the `cd` fails (the folder was renamed, the hook runs outside
  the repository), bash's `cd` exits 1 and the hook exits 2, blocking the agent with no way
  out. Tried: `bash --posix -c 'cd /nonexistent && echo y || { [ $? -eq 1 ] && exit 2; }'`
  exits 2; dash's `cd` exits 2 and so would not block, and macOS's `/bin/sh` is bash. With
  the braces a failing `cd` exits 1, a non-blocking hook error.
- **Raised 2: the folder inside the double quotes.** The brief says "quoted as in record 8",
  but record 8's single quotes cannot go inside `"..."`, where they would be taken
  literally. Inside double quotes a space needs nothing, so `apps/my atelier` is written as
  it is; of the characters double quotes do not protect, `"`, `$`, `` ` `` and `\` each get
  a `\` in front (documented, not tested: no project folder is named so). The pre-commit and
  CI commands keep record 8's form.

**Raised 3, for the owner, not built: a merge or rebase after the session committed.**
`--session` is `--base <start>`, so commits that reach `HEAD` and not the start count as
the session's work. When the session merges `main` after its own commits, or rebases onto
it, `main`'s commits since the branch left it count too. Tried on the record 8 build
(`qa-a2/repos/shaper-h1`): a branch, the session start on it, `main` changes
`app/orders.rb` without its record; during the merge `check --staged` passes (record 8);
after the merge commit `check --base <start>` lists `place-order` `app/orders.rb`, exit 1;
the same after a rebase. So the agent is held until it confirms a record for `main`'s
change. Only `main`'s commits that left a record behind are reported: a `main` that passes
its own gates reports nothing. A rule that would remove it: the parents of a merge made in
the session, other than the first, count as part of the base, as during a merge in
progress (record 8: "the other side's work was judged where it was made"). Its cost: a
session's own side branch merged with `--no-ff` would then pass the Stop hook, caught only
by the pre-commit hook and CI; a rebase stays as it is. Left as the brief has it.

### H2. `--help`

- `roostr --help`, `roostr -h`, and `--help` or `-h` among the arguments of any of roostr's
  commands, before `--`, print the usage on stdout and exit 0, doing nothing else: no
  project needed, no file written, no Git read. **Proposed:** the usage is the one text
  `roostr --help` prints, for every command (small: one text to keep current). `--help`
  is never the value of an option (as `--json`).
- **Proposed:** an unknown command stays an unknown command with `--help` after it
  (`roostr frobnicate --help` exits 2), as with Git and Cargo.
- Every other unknown option stays exit 2 with the usage on stderr.
- `show -- --help` still looks up the id `--help`.
- `roostr session start --help` prints the usage on stdout, the one exception to "nothing on
  stdout": a hook never passes it.
- The usage names `roostr session start` and `check --session`.

### H3. macOS

The release and CI will run the whole suite on `macos-15` (arm64) and `macos-15-intel`.
Reviewed by reading; what was found and done:

- **Tools in fixtures and the kit.** The fixture scripts are POSIX `sh` (`cat` heredocs,
  `printf`, `basename`, `sleep 5 &`, `case`), the fake `git`s too; no `sed -i`, `stat -c`,
  `readlink -f`, `date -d`, `timeout`, `seq`, `awk`, `/proc`. The kit is Ruby: process
  groups and `kill -KILL -<pgid>` work on macOS (its `EPERM` for a group of zombies is
  already rescued). `git_not_on_the_path` links `sh`, `cat`, `touch`, `basename` and `env`,
  all in `/bin` or `/usr/bin` on macOS. Git runs with no system or global configuration
  (`GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL=/dev/null`), so neither Homebrew's nor Xcode's
  `gitconfig` reaches it. The new hook tests run `bash -c`, the shell macOS's `/bin/sh` is.
- **Temporary folders.** On macOS `Dir.mktmpdir` gives `/var/folders/...`, a symbolic link
  to `/private/var/...`, while Git and `getcwd` give the real path. No test asserts an
  absolute path, but **changed:** the kit now takes the real path of every folder it makes,
  so the test's paths and the program's agree on both systems.
- **Letter case.** No test creates two files whose names differ only in case in one folder
  (checked over every `write_file` and the fixtures). `show BOOK-WORKSHOP` (record 6)
  expects exit 1 with a suggestion: on a file system that ignores case, a roostr that opens
  `.roostr/processes/<id>.yml` would find `book-workshop.yml` and exit 0, so that test
  catches it on macOS. Likewise `Refund-Booking.YML` (record 8) expects the finding to name
  `Refund-Booking.yml` as the name to rename to: a roostr that asks whether that path
  exists would find the `.YML` file itself on macOS and call the name taken. Both kept as
  they are; see notes for the worker.
- **Non-ASCII file names.** One test depends on one: `app/gift cards/café.rb`
  (`check_processes_test`), written precomposed (NFC) by Ruby, listed precomposed in the
  record. APFS keeps a name as it was written, and Git on macOS precomposes what it reads
  (`core.precomposeunicode`, which `git init` sets there), so roostr sees NFC from Git and
  from the record. **Decided:** kept, as the one test that a decomposed name would break.
  The JSON values with accents are file contents, not names.
- **`TESTING.md`** says what the suite needs, on Linux and macOS: Ruby 3.0 or later with
  Minitest (the Ruby macOS ships, 2.6, is too old), Git 2.28 or later, `sh`, `bash` and the
  usual tools on the `PATH`.

What could not be made certain, for CI on macOS to prove:

- that APFS on the runners keeps `café.rb` precomposed, and that roostr compares it as Git
  reports it;
- that the 3-second limit of `assert_finished_within` (record 8) holds on a slow runner;
- that Claude Code runs a hook's command with bash, or with `sh`: the tests use bash, which
  is the stricter for Raised 1;
- the macOS kernel's answer for a script whose `#!` line names a missing interpreter (the
  Windows-line-endings tests expect it cannot be started, as on Linux; it should be
  `ENOENT` on both);
- that nothing in the build itself is Linux-only: the worker's side.

## Test kit

- `session_start` (with `id`, `source:`, `today:`, `stdin:`, `from:`) and `check_session`
  (with `id:`, `stdin:`) run the two commands with the input Claude Code gives the hook, and
  say so under a failure. `SESSION` is the default id.
- `claude_code_runs "Stop", command` runs a hook's command as Claude Code does: `bash -c`,
  in the folder given, with the input on stdin and roostr first on the `PATH`.
- `linked_worktree "second-checkout"` and `remove_the_last_commit_for_good` in the
  workspace.
- `assert_written_only_under ".git/roostr/sessions/"`: the last command wrote something,
  and everything it created, changed or deleted, the Git folder included, is in that
  folder. `assert_nothing_written git_folder: true`: nothing, the Git folder included. The
  snapshot before a command is taken after the kit's own `git status`, which may refresh
  the index.
- Every folder the kit makes is taken by its real path (macOS).
